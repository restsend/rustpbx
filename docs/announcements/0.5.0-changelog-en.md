# RustPBX 0.5.0 — Detailed Changelog

> Single-binary, programmable SIP PBX in Rust — a modern alternative for FreeSWITCH/Asterisk users and voice-agent developers.

**1,874 commits · 13 contributors · 708 files changed** since 0.4.6 (June – September 2026). This release rebuilds the media engine, ships production-grade queueing/ACD in the community edition, and matures the RWI control plane for AI call automation. It is the largest release so far — read the [Breaking Changes](#breaking-changes--upgrade-guide) section before upgrading.

Condensed version for the GitHub Release page: [0.5.0-release-en.md](0.5.0-release-en.md) · 中文公告: [0.5.0-release-zh.md](0.5.0-release-zh.md)

## Highlights

### 1. Media engine rewrite: faster, leaner, lossless

- **~6.4 ms** end-to-end call setup — **2.7× faster** than the previous media layer;
- Same-codec calls (including WebRTC↔WebRTC and WebRTC↔RTP) take a **zero-copy fast-path relay** at ~0.14% core / ~0.57 MB per channel, with automatic transcode fallback;
- **WebRTC ↔ legacy SIP/RTP interop is native**: 800 concurrent cross-transport relayed calls and 500 concurrent Opus↔PCMU transcodes, both at **0% packet loss**;
- An 18,000-call soak test showed flat memory and no sequence/timestamp jumps — no audio glitches.

### 2. 5,000 concurrent calls with full recording on < 4 cores

Real-world regression, not a lab number (CPS=200 call storm + continuous stereo recording + MySQL CDR):

| Phase | rustpbx CPU | MySQL QPS | Notes |
|---|---|---|---|
| Ramp-up — 200 CPS INVITE storm | 280–380% | 2–6 | auth & extension lookups all cache-hit |
| Steady state — 4,943 concurrent recorded calls | **380–390% (≈3.9 cores)** | 2–4 | ≈ +0.13% core / +0.13 MB per recorded call |
| Teardown — ~5k BYE/CDR burst (~90 s) | declining | peak 277 | 4,980 stereo WAVs (4.4 GB), zero drops |

Completion 4,943/5,000 answered, 100% progress, **0.00% packet loss**, no leaks. During calls the database is nearly idle — capacity planning reduces to **≈ 0.08 core per recorded channel**, scaling linearly.

### 3. Queue & ACD join the community edition

- **Skill-group routing** and **escalation plans** (match agents by skill, escalate on wait timeout);
- **Concurrent agent dialing** — ring multiple agents at once, first answer wins;
- The **supervisor toolkit**: `listen` / `whisper` / `barge` / `takeover` in a single RWI command, including cross-session takeover;
- Agent sign-in/out, wrap-up states, and full queue-entry tracing.

### 4. RWI: the remote control for voice agents

RWI is RustPBX's real-time control protocol — JSON over WebSocket, an AMI-style action/event model without the legacy baggage. 0.5.0 covers more of the call lifecycle:

- **Record from early media** (`record.start` works in the ringing phase);
- **REFER blind-transfer with B2BUA fallback** — when the peer doesn't support REFER, the transfer degrades to a bridge transfer and the call is never dropped;
- **Bidirectional PCM audio streaming** (`voip_bridge:`/`bridge:` endpoints), conference `create/add/remove/mute/end/merge`, `call.transfer.replace` (RFC 3891), `dtmf.collect`, `app.chain`.

Combined with the HTTP Router's inbound webhook, one integration covers answer, playback, transfer-to-human, recording, and monitoring.

### 5. Live transcription & predictive outbound: first-class AI primitives

- **Live transcription SSE**: `GET /cc/calls/{call_id}/transcript` with independent ASR streams for both legs, speaking the Deepgram-compatible streaming protocol (16 kHz PCM / 20 ms frames). Lazy start — it runs only while someone subscribes, never touching the media path;
- **Offline transcription**: local SenseVoice engine produces full transcripts on hangup, data stays in-network;
- **Predictive outbound SSE**: `POST /ami/v1/outbound/dial` starts a call with one HTTP request; standard RWI events (`created → ringing → answered → bridged`) stream back over SSE, with `on_answer` hooks.

ASR results, DTMF, and call-state events push over the same WebSocket — your voice agent needs exactly one connection.

### 6. Clusters, containers, graceful shutdown

- `[cluster]` multi-node networking with a **distributed session registry** ("which node owns this call?"), request auto-forwarding, and cluster-wide config dispatch;
- **SIGTERM drain-then-exit**: finish in-flight calls before exiting — rolling deploys don't drop calls;
- Stateless-friendly storage: recordings/CDR/signaling upload to S3, sessions live in shared PostgreSQL/MySQL — add replicas to scale.

- Zero-copy fast-path relay for all same-codec transport combinations, with transcode fallback (`40dd791a`);
- New codecs: **Opus** and **G.729**, 48 kHz telephone-event DTMF (`cafcec33`, `1753ced3`, `719de07b`);

- WebRTC↔RTP SDP bridging and per-leg negotiated media profiles (`d7eda01d`, `b2e0a473`).

- Supervisor listen/whisper/barge/takeover with cross-session takeover (`0ecfca32`);

## Performance

- **5k-CC recording collapse fixed** (`7c37af8c`): recorder queue sizing, dedicated media runtime for recording tasks, SIP workers scaled to cores/2 — from 17.7% packet loss at 3.3k concurrent to **4,943 concurrent recorded calls at 0% loss**;
- SIP signaling and RTP media now run on **isolated tokio runtimes** (`7b82ba88`);
- ~130 hot-path heap allocations removed; RWI memory leak fixed (`c72bf042`);
- Memory locator switched from `tokio::Mutex` to `DashMap`; faster registration sweeps (`49262229`, `e0345b94`);
- SipFlow ingest/flusher throughput + jemalloc by default (`f0429cb0`, `c841228f`);
- Faster proxy failover: earlier 100 Trying and no-trying timeout (`3c005717`).

Full benchmarks: [tests/bench/bench.md](../../tests/bench/bench.md), [docs/capacity-planning.md](../capacity-planning.md), and the README benchmark section.

## Breaking Changes & Upgrade Guide

### Recording & SipFlow
- **`[sipflow]` alone no longer captures RTP.** RTP capture now requires an explicit recording config:

  ```toml
  [recording]
  enabled = true
  type = "sipflow"   # signaling-only capture is unchanged
  ```
- `callrecord` storage now defaults to `type = "database"` (previously local JSON files in examples). Configure `[callrecord]` explicitly for local files, S3, or HTTP upload.
- Recording auto-start point is configurable (early media vs answer).

### SIP behavior
- `session_timer` now defaults to **`true`** (RFC 4028, Supported mode);
- `video_codecs` defaults to `["H264", "VP8"]`; new `video_policy` option (`pass_through` / `strip` / `transcode`);
- New NAT/network controls: `sip_external_ip`, `auto_sip_external_ip`, `local_networks`, `[[network_profile]]` — review your NAT setup if you relied on implicit defaults.

### RWI protocol (the biggest changes)
- Event rename: **`call_incoming` → `call_created`**;
- Removed commands: `media.stream_start` / `media.stream_stop` / `inject_start` / `inject_stop` — use `call.transfer` to a **`voip_bridge:`/`bridge:` WebSocket endpoint** (binary PCM16 frames) for real-time audio; `record.mask_segment` removed;
- Removed events: `dn_state_changed` / `dn_registered` / `dn_unregistered`, `call_metadata_updated`, `ivr_flow_transitioned`, `queue_overflowed`, `parallel_originate_*`, `session_resumed`, `media_stream_started`/`stopped`, `record.segment_masked`;
- **`record_stopped` no longer carries the recording URL** — listen for `record_end` / `recording_metadata_available`;
- Renamed event: `supervisor.takeover.completed` → `supervisor.takeover.started`;
- Parameter changes: `call.originate` (no `hold_music`/`hold_music_target`), `queue.enqueue` (no `skills`/`max_wait_secs`), `conference.create` (no `backend`/`record`);
- Event field changes: `ani`/`dnis`/`root_call_id`/`operation_id` removed; `caller`/`caller_name`/`callee_name`/`trace_id`/`hangup_by`/`duration_secs`/`transfer_target` added;
- Config keys `[rwi].enabled` and `[rwi].contexts` removed;
- `[rwi.smart_routing]`, `[rwi.local_rules]`, `[rwi.sip_header_passthrough]` are now explicitly documented as **design proposals, not implemented** — don't rely on them.

### Console / HTTP API
- All console JSON endpoints are unified under the **`/api` prefix** behind an auth middleware with a CSRF guard; new static Bearer token auth via `[console].api_tokens` with scopes;
- The `/licenses` list route was removed (`/licenses/verify` remains);
- Locator/registration payloads changed: `aor` is now a full `IP:port` address, `destination` carries a transport prefix, and new fields were added (`home_proxy`, `supports_webrtc`, `transport`, `user_agent`, `expires`).

### Removed components & config
- Addons removed: `endpoint_manager`, `enterprise_auth`, `sbc`;
- Config keys removed: `[proxy].sip_flow_max_items`, `media_cache_path`;
- `verify-i18n` binary removed; new `rustpbx dump` subcommand exports the DB DDL;
- The `opus` Cargo feature was removed — Opus is always available via audio-codec.

### Deployment
- **Source builds now require submodules**: `git clone --recurse-submodules` (addons `cc`, `wholesale`, `ivr_editor`, `telemetry`, `voicemail` are submodules now);
- Docker image: base moved to `debian:trixie-slim`, `libopus0` no longer needed, sounds moved to `/app/config/sounds` (a compat symlink at `/app/sounds` is kept);
- New environment variables: `DEEPGRAM_API_KEY` (remote transcription), `CC_PHONE_AUTH_SECRET` (phone auth).

### Database
- Migrations run automatically on startup (disable with `--skip-migrate`); this release adds three: `outbound_sip_trunk_id` column on call records, `config_entries` table (DB-backed config), `cluster_sessions` table (cluster session registry);
- Stale migration records are pruned and self-healed at startup;
- Stack upgrades: sqlx 0.8 → 0.9, sea-orm 1.1 → 2.0.

## Upgrading

```bash
docker pull ghcr.io/restsend/rustpbx:latest
# or from source:
git clone --recurse-submodules https://github.com/restsend/rustpbx.git
```

Review the [Breaking Changes](#breaking-changes--upgrade-guide) above — in particular the RWI event renames and the recording configuration — then start the new binary; database migrations run automatically.
